TL;DR

The problem, my decision, the impact.

Problem

An incomplete handoff file, and HTML and accessibility rules missing from the design system.

Decision

A validation workflow before development, and component documentation that builds in RGAA.

Impact

More realistic delivery, aligned with developers, and a 5-step process shared across 5 tools.

Context & challenge

One product per designer, one system to share.

The Télérecours e-filing platform underwent a visual redesign. User research was launched alongside it to improve existing features. Each product had its own designer, responsible for its interface.

My role: support each designer, synchronize changes across products, centralize them in a library and share it with all designers.

Key issues

P1 · HANDOFF

A handoff file to improve

The Ready to Dev file did not yet give developers all the information they needed to implement the mockups.

P2 · ACCESSIBILITY

Missing functional and accessibility rules

HTML attributes and roles, as well as RGAA recommendations, were not built into the components.

Main challenge

Delivery that is as realistic as possible, aligned with developers.

Approach

Validate before building.

Have every new feature validated by design and engineering, even before refinement.

The workflow for a new feature — three steps added before development

  1. Design

    The designer designs the feature.

  2. Design review

    Added

    Consistency with the design system and accessibility rules.

  3. Tech review

    Added

    Feasibility assessment.

  4. Sharing before refinement

    Added

    Early discussions with developers.

  5. Refinement and development

    A feature that has already been discussed and is realistic.

Sources for RGAA recommendations · French Government Design System (DSFR) · MDN Web Docs (Mozilla)

A 5-step process to add a component to the design system

  1. Prioritize

    Based on the roadmap.

  2. Inventory

    From each tool's design files (TR-AVO, TR-ADM, POCO, TRC).

  3. Document

    Based on the French Government Design System.

  4. Harmonize

    With the foundations.

  5. Deploy

    Publish and share the library.

Key decisions

Three decisions to align design and development.

Each decision addresses a specific problem and results in a practice still in place at the end of the engagement.

D1

A validation workflow before development

Finding
A Ready to Dev file that did not give developers all the information they needed.
Decision
Add a design review and a tech review, and share features ahead of refinement to discuss them with developers.
Impact
3 steps addeda feature already discussed and realistic before development.
D2

Documentation with accessibility built in

Finding
HTML attributes, roles and RGAA recommendations were not built into the components.
Decision
Document every component: states, keyboard interactions, HTML elements, roles and attributes, RGAA criteria to check, based on the DSFR and MDN.
Impact
RGAA built inHTML rules and RGAA recommendations are part of the component documentation.
D3

A shared process for all designers

Finding
One product, one designer: changes lagging behind in the library and documentation to strengthen.
Decision
A 5-step workflow, from roadmap to deployment, to add every component to the design system.
Impact
5 designersaligned around a shared design system, across the 5 tools.
